Problem Statement & Motivation

Systemic Security Gaps in Modern Engineering

Analysis of critical vulnerabilities in modern software supply chains and developer workflows

1. Secret Leakage in Persistent Git Trees

  • Accidental Commits: Developers push API tokens, private keys, and cloud credentials directly into version control.
  • Persistent History: Deleting a token in a later commit does not purge it from git history; attackers easily extract objects from commit graphs.

2. Open-Source Supply Chain Risks (SCA)

  • High Dependency Ratio: Over 85-90% of modern software consists of third-party open-source libraries.
  • Transitive CVEs: Deep dependency trees hide critical unpatched vulnerabilities (Log4Shell, prototype pollution) without developer awareness.

3. Developer Alert Fatigue & Unactionable Output

  • High False Positives: Traditional static analysis tools dump hundreds of unranked warnings lacking business context.
  • Missing Remediations: Tools flag what is broken, but fail to provide contextual, copy-paste code patches.

4. Tool Fragmentation & Runtime Blindness

  • Tooling Silos: Separate CLI scripts for secrets, SCA, and SAST prevent centralized governance and immutable audit trails.
  • Runtime Gap: Static analysis evaluates code at rest, leaving running servers blind to live HTTP reconnaissance attacks.

System Architecture

Single-Origin FastAPI & React SPA Request Architecture

Eliminating cross-origin vulnerabilities while maintaining strict boundary separation

Tier 1: Presentation Layer (Vite + React 18 SPA)

frontend/src

• Strict Route Isolation: Completely separated routing shells for /admin/ (Directory, Audit, Security Dashboard, Filesystem) and /user/ (Workspace, Projects, Scans). No shared navigation components.
• Path Separation Principle: UI page routes (/admin/directory) are strictly decoupled from JSON API endpoints (/admin/users).
• Client-side Visualizations: ApexCharts telemetry graphs, finding detail side-drawers, and live scan progress indicators.

Tier 2: API Gateway & Security Middleware (FastAPI)

backend/app

• Single-Origin Serving: FastAPI serves both the JSON API routes and the compiled React SPA assets from a single port (8000), eliminating CORS attack surfaces.
• Auth & Session Guard: Enforces veritas_session cookie verification, role-based access control, and in-memory rate limiting (429).
• Passive HTTP Telemetry: Middleware inspects paths, query parameters, and headers for SQLi, XSS, SSRF heuristics (never stores request bodies).
• Webhook Gateway: Validates X-Hub-Signature-256 HMAC signatures on incoming GitHub push notifications.

Tier 3: Execution & Persistence Layer (Async Runner + DB)

services/ & models/

• Ephemeral Sandboxes: Short-lived workdirs (/tmp/veritas-scans) automatically wiped clean upon scan completion or cancellation.
• Multi-Engine Dispatcher: Orchestrates 12 CLI security tools with normalized output schemas (severity, CWE, file, line, fingerprint).
• Dual-Tier AI Pipeline: OpenRouter hot-file contextual code review + Groq Llama-3 synthesis with fail-open fallback.
• Persistence: SQLAlchemy 2.0 with SQLite in development and PostgreSQL in production. SHA-256 tokens and Fernet-encrypted GitHub secrets.

Slide 4 Talking Points:
Let's look at the software architecture. VERITAS employs a unified single-origin model: FastAPI serves both the backend APIs and the compiled React frontend. Why? Because hosting the SPA on the same origin completely eliminates CORS exposure and allows secure HttpOnly session cookies to work natively without cross-domain leakage.

Notice the strict boundary: Admin routes and User routes have completely separate navigation trees. In the backend, our background runner executes scans inside temporary sandboxes and purges them immediately after completion.

Cryptographic Defense

• Argon2 Hashing: Memory-hard parameters resistant to GPU/ASIC cracking.
• SHA-256 Hashes: Sessions, verify tokens, and reset tokens stored exclusively as hashes.
• Fernet Encryption: GitHub OAuth access tokens encrypted at rest via AES-128-CBC + HMAC.

Authorization Guardrails

• Fail-Closed Gate: Users cannot bypass admin approval to access workspace APIs.
• Anti-Demotion Lock: System blocks deactivating or demoting the last active administrator.
• No Self-Role Changes: Administrators cannot alter their own roles to prevent privilege escalation.

Geolocation Audit Trail

• Immutable Trail: Append-only table logging logins, failures, approvals, and scans.
• IP Consensus: Resolves client location across ip-api, ipwho.is, and ipapi.co.
• Rich Context: Captures HTTP response status codes (200, 401, 429) for forensic tracing.

Operational Controls

Triage Workflow, Diff Scans, Suppressions & Quotas

Granular developer control to eliminate duplicate alert fatigue and enforce policy gates

1. Finding Status Lifecycle & GitHub Blobs

• 4 Strict Statuses: open, triage, fixed, false_positive.
• Slide-out Finding Drawer: Inspect vulnerability severity, engine source, code snippets, and remediation instructions.
• Direct GitHub Blob Links: One-click navigation directly to the vulnerable line: github.com/{repo}/blob/{sha}/{path}#L{line}.

2. Cryptographic Suppression Fingerprints

• Fingerprint Formula: SHA-256(engine|rule_id|file_path|line_start|title).
• Cross-Scan Memory: Once marked suppressed, re-scans automatically classify matching fingerprints as false_positive.
• Eliminates annoying re-triaging of previously resolved or accepted risks.

3. Scan Compare / Diffing Engine

• Side-by-Side Commit Comparison: Compare Scan A vs. Scan B across any two branch commits.
• Tri-State Diff: Instantly categorizes findings into Newly Introduced, Resolved, and Unchanged.
• Severity Policy Gates: Configurable fail_severity (critical, high, medium) auto-fails scans violating quality thresholds.

4. Compute Quotas & Cooperative Cancellation

• Compute Quotas: Enforces SCAN_RATE_LIMIT (10/hr) and SCAN_CONCURRENT_LIMIT (2) to prevent host exhaustion.
• Cooperative Cancellation: Users can cancel scans; workers evaluate cancellation flags between engine stages.
• Ops Alerts: Automatic email alerts dispatched to admins when engine binaries are missing or clone fails.

Slide 9 Talking Points:
Scanning is easy; managing vulnerabilities at scale is hard. VERITAS provides complete operational governance:
1) Finding lifecycle: A developer can triage findings and click directly into the exact line in GitHub's code viewer.
2) Cryptographic suppressions: Using SHA-256 fingerprinting, once a false positive is suppressed, the system permanently remembers it on future scans.
3) Scan compare: Security teams can compare two scans to see exactly which bugs were fixed or added in a release.
4) Rate limits and cooperative cancellation prevent server exhaustion.

Defensive Engineering

Platform Security Posture & Fail-Closed Safeguards

Practicing what we preach: robust hardening of the VERITAS application itself

Security Domain Implementation & Mechanism Threat Mitigated & Defensive Value
Session Security veritas_session with HttpOnly, SameSite=Lax, and Secure flags. SHA-256 hashed DB tokens. Prevents XSS session theft and eliminates exposure of valid sessions if database backups are compromised.
Account Recovery Password resets immediately revoke all active session rows across all user devices. Eliminates lingering sessions if an account was compromised prior to password reset.
Authorization Guardrails Fail-closed role checks. Blocks demoting the last active admin; admins cannot alter own role. Mitigates privilege escalation attacks and prevents accidental platform lockout.
Filesystem Protection /admin/files restricts traversal; blocks /proc, /sys, /dev, /etc/shadow, and .env. Prevents Local File Inclusion (LFI) and accidental disclosure of server credentials.
Slide 12 Talking Points:
As a cybersecurity platform, VERITAS must be thoroughly hardened itself. We built this following defense-in-depth principles:
- Session security: HttpOnly cookies, SHA-256 database token hashing, and instant session invalidation upon password reset.
- Authorization guardrails: Unauthenticated requests fail closed, and administrators cannot escalate their own roles or delete the last admin.
- Workspace security: Host filesystem exploration restricts system paths, and git clones are destroyed immediately after scanning.
